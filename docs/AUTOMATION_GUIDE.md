# 자동화 실행 가이드 (장마감 즉시 실행)

이 문서는 **매일 장마감 후 자동으로 실행되는 세션**(Claude Code Remote Routine)이 따라야 할
절차다. 스케줄된 세션이 이 문서를 읽고 그대로 수행한다.

리포트 양식은 `reports/sample/2026-08-24_sample.json`을 렌더링한 결과가 기준이다.

## 0. 시간 목표 — 15:30 장마감, 15:40까지 완성

한국 증시는 15:30에 마감한다. 이 Routine은 15:30 KST에 즉시 발동되며, **늦어도 15:40 KST까지
리포트 완성 + 전달 + 커밋까지 끝내는 것이 목표다.** 10분 안에 끝내려면:

- 검색은 **핵심 검색어 위주로 8~10개 내외**로 제한한다. 같은 항목을 여러 번 다르게
  검색하며 파고들지 말 것 — 신뢰할 수 있는 소스에서 한 번에 확인되면 바로 쓰고, 안 나오면
  1~2회 더 시도한 뒤 그래도 없으면 "-"로 비우고 다음으로 넘어간다.
  (아래 "소싱 원칙"의 신뢰 소스 제한과 함께 적용 — 못 찾았다고 아무 사이트나 더 뒤지지 않는다.)
  질문·확인을 위해 사용자에게 되묻지 않는다 ("결과 전달" 단계 전까지는 완전히 혼자 진행).
- 여러 항목을 조사할 때는 한 번의 검색으로 여러 필드를 동시에 확인할 수 있는 포괄적인
  검색어를 우선한다 (예: "코스피 코스닥 마감 시황 삼성전자 SK하이닉스" 처럼 묶어서).
- 아래 "1페이지 원칙"대로 항목 수 자체를 적게 유지하면 조사량도 자연히 줄어든다.

## 1. 소싱 원칙 — 뉴스 또는 공식 거래소/API만, 허위정보 절대 금지

- 데이터 출처는 **① 언론사 뉴스 기사, ② KRX 등 공식 거래소 데이터, ③ 사용자가 제공한
  토스증권 Open API(`scripts/toss_client.py`, 이 환경에서는 접속 차단되어 있으니 접속 가능한
  환경에서만)** 로 한정한다.
- **나무위키 등 사용자 편집 위키, 개인 블로그, 포워드/주가예측 사이트(예: AI가 미래 주가를
  추정해 보여주는 사이트), 출처 불명 요약 사이트는 근거로 쓰지 않는다.** 검색 결과에 이런
  출처가 섞여 있으면 걸러내고 언론사 기사·거래소 자료만 채택한다.
- 확인 안 되는 수치는 **절대 지어내지 않는다.** "-"로 비우거나 방향성만 정성적으로 쓴다.
  이건 타협 대상이 아니다 — 틀린 숫자가 나가는 것보다 빈 칸이 훨씬 낫다.
- 여러 소스 수치가 다르면 더 신뢰도 높은 소스(언론사 기사 본문의 구체적 수치, 거래소 공식
  발표)를 우선하고, 그래도 불확실하면 "(추정치)"라고 표기한다.

## 2. 문체 원칙 — "AI가 쓴 티" 내지 않기

- 짧고 단정하게. "~것으로 보인다", "~라고 판단된다", "~할 필요가 있다" 같은 헤지 표현을
  문장마다 반복하지 않는다. 사실을 먼저 던지고 근거를 붙이는 순서로 쓴다.
  예) "삼성전자가 8.88% 급락했다. 주주환원안이 시장 기대에 못 미쳤다는 평가다." (O)
      "삼성전자의 경우 주주환원안 발표가 있었으나 시장의 기대에는 다소 못 미쳤던 것으로
      보이며, 이로 인해 주가가 하락한 것으로 판단된다." (X — 장황하고 얼버무림)
- 뻔한 전환어("이는 ~를 시사한다", "한편", "특히 주목할 점은") 남발 금지. 문장 사이 연결은
  내용 자체로 하고, 필요할 때만 최소한으로 쓴다.
  - 실제 데스크 노트처럼 숫자·고유명사를 먼저 말하고 해석은 짧게 붙인다.

## 3. 1페이지 원칙 — 항목 수를 적게

인쇄/PDF 기준 1페이지 안에 들어오는 게 가장 좋다. 항목 수를 다음 범위로 제한한다:

- `issue_stocks`: **3~4개** (많이 나열하지 않는다 — 시총 크거나 등락률 크거나 관심도
  높은 것 위주로 압축)
- `calendar`: **4~5개**
- `sectors`: 10~15개는 괜찮다 (히트맵은 항목 수가 늘어도 세로 길이가 늘지 않는다)
- `signal`/`key_point`/`step`, `sector_prose`: 각각 1~2문장. 3문장 넘기지 않는다.

## 절차

1. **오늘 날짜/거래일 확인.** 오늘이 한국 증시 휴장일(주말/공휴일)이면 리포트를 생성하지 말고
   종료한다.

2. **헤드라인 잡기.** `title`(굵은 제목), `subtitle`(보충 한 줄), `eyebrow`("시장 마감 브리프"
   고정)와 SIGNAL/KEY/STEP 세 줄(각 1~2문장)을 위 원칙대로 작성한다.

3. **Ⅰ. 지수·대외 지표 조사.** `indicators` 배열: KOSPI·KOSDAQ 종가/전일비/등락률,
   원/달러, 미 10년물, S&P500 선물/WTI. 각 행에 `note`(왜 중요한지 한 줄). `flows`(외국인/
   기관/개인 순매수)와 `breadth`(상승·하락 종목수, 거래대금, 신용잔고)도 조사하되, 1번 원칙대로
   못 찾으면 "-".

4. **Ⅱ. 업종 동향 조사.** `sectors`: 업종별 `change_pct`와 **실제 시가총액 비중을 반영한
   `weight`** (반도체가 특히 크다 — 대충 비슷하게 나열하지 않는다). `sector_prose` 1~2문장.

5. **Ⅲ. 이슈 종목 조사.** `issue_stocks` 3~4개. 각각 `name`/`ticker`/`change_pct`/
   `reason`(왜 움직였는지, 근거 포함)/`persistence`("높음"/"중립"/"약세 지속")/
   `checkpoint`(다음에 뭘 언제 확인할지).

6. **Ⅳ. 캘린더 조사.** `calendar` 4~5개, 날짜순. 각각 `datetime`/`event`/`importance`(1~3)/
   `checkpoint`.

7. **지점 대응 요약.** `stance.maintain`/`reduce`/`cash` 각 1문장.

8. **데이터 JSON 작성.** `data/{YYYY-MM-DD}.json`에 정리 (`data/` 없으면 생성).
   `reports/sample/2026-08-24_sample.json`을 스키마 예시로 참고.

8-1. **(선택) 차트 생성.** 2번에서 조사한 최근 며칠치 KOSPI/KOSDAQ 종가가 있으면
   (뉴스에 "최근 5거래일 코스피 추이" 같은 표/문장이 나오는 경우가 많다) 차트를
   만들어 넣는다. 못 찾았으면 생략해도 된다(리포트에서 그 부분만 빠질 뿐 깨지지 않음).
   ```
   python3 scripts/build_chart.py --out reports/{YYYY-MM-DD}_chart.png \
     --kospi "08/18,6820.10;08/19,6830.50;...;{오늘},{종가}" \
     --kosdaq "08/18,845.20;...;{오늘},{종가}"
   ```
   생성됐으면 데이터 JSON에 `"chart_png_path": "reports/{YYYY-MM-DD}_chart.png"`를 추가한다.

9. **렌더링 실행 (3개 포맷 모두).**
   ```
   python3 scripts/render_report.py data/{YYYY-MM-DD}.json
   cd scripts/docx && npm install && cd ../..
   node scripts/docx/render_docx.js data/{YYYY-MM-DD}.json reports/{YYYY-MM-DD}_market_report.docx
   ```
   `.md`/`.html`/`.docx` 세 파일이 모두 `reports/`에 생성된다.

10. **검증.** `.md`를 열어 표가 깨지지 않았는지, TODO/빈 값이 남아있지 않은지 확인.

11. **결과 전달.** `SendUserFile`로 `.html`과 `.docx`(용량 크지 않으면 `.md`도)를 사용자에게
    보낸다. 메시지에는 오늘 KOSPI/KOSDAQ 등락률과 SIGNAL 한 줄을 요약해 포함한다. 사용자가
    먼저 뭔가 보내지 않아도 매일 이 절차가 자동으로 실행되는 것이 정상이다 — 확인 질문 없이
    끝까지 진행한다.

12. **저장소에 커밋.** `data/{YYYY-MM-DD}.json`과 `reports/{YYYY-MM-DD}_market_report.md/.html/.docx`를
    커밋하고 지정된 브랜치에 푸시.

## 참고: 로컬 PC/사내 서버에서 "진짜 시세 API + 차트"로 완전 자동화하려면

이 원격 세션 환경(이 문서를 따르는 Claude Code Remote Routine이 도는 곳)은 조직
보안 정책상 KRX/증권사 API 서버에 직접 접근이 막혀 있다 (`data.krx.co.kr`,
`openapi.tossinvest.com` 모두 확인됨 — curl로 직접 테스트해도 403). **그래서 이
문서의 기본 경로는 WebSearch로 뉴스를 읽어 데이터를 채우는 방식이고, 정밀한
실시간 시세나 실제 가격 차트는 이 환경에서는 만들 수 없다.** 정확한 API 시세와
차트가 꼭 필요하면 방화벽 제약이 없는 사용자의 로컬 PC나 자체 서버에서 도는
별도 파이프라인이 필요하다 (이건 이 Routine이 아니라 사람이 그 PC/서버에
크론으로 설정해야 한다):

- **`scripts/run_local.sh`** — 로컬에서 장마감 직후 실행하는 원스톱 스크립트.
  `scripts/fetch_pykrx.py`로 지수·등락률 상위종목·최근 10거래일 차트(PNG)까지
  몇 초 안에 자동 수집한 뒤, 제목/SIGNAL·KEY·STEP/이슈종목 이유/캘린더/지점
  대응처럼 **판단이 필요한 항목만** TODO로 표시해서 사람이 채우게 하고, 그 다음
  `.md`/`.html`/`.docx`를 렌더링한다. `--auto`로 실행하면 TODO를 그대로 둔 채
  바로 렌더링한다(사람 개입 없이 크론으로 돌릴 때).
- 이렇게 하면 **가격·차트는 pykrx 실시간 데이터로 몇 초 안에 정확하게**, "왜
  움직였는지" 같은 판단은 사람이 자기가 이미 아는 내용으로 빠르게(보통 뉴스
  검색보다 훨씬 빠름) 채우는 구조라 15:30~15:40 목표를 실제로 맞출 수 있다.
- `scripts/toss_client.py`(`.env`에 `TOSS_API_KEY`/`TOSS_API_SECRET` 필요, 사용 전
  https://developers.tossinvest.com 문서와 엔드포인트 대조 검증 필수 — 아직
  미검증)로 pykrx 대신 토스증권 시세를 가져오는 것도 가능하다.
- 판단이 필요한 항목까지 사람 개입 없이 완전 자동화하려면, 이 로컬 스크립트가
  만든 정확한 숫자 JSON을 Claude API(WebSearch 툴 포함)에 넘겨 이유·캘린더·
  지점 대응까지 채우게 하는 구조를 추가로 만들면 된다 — 지금은 구현돼 있지
  않다.

크론 예시 (평일 15:30 KST 장마감 직후, 사람이 나중에 확인):
```
30 15 * * 1-5 /path/to/Daily/scripts/run_local.sh >> /path/to/Daily/logs/run.log 2>&1
```
(터미널이 없는 크론에서 바로 완성까지 원하면 `run_local.sh --auto` — 단, 이 경우
이유/캘린더/지점 대응 등은 TODO로 남는다.)
